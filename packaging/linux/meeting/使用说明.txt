周例会纪要机器人（Linux）使用说明

一、怎么用（三步）

1. 把整个「周例会纪要机器人」目录解压到服务器本地磁盘（例如 /opt/meeting-minutes-bot）。
2. 进入目录后执行：chmod +x 启动机器人.sh 停止机器人.sh 查看运行日志.sh
   然后执行：./启动机器人.sh
   首次启动要加载文字识别模型，大约十几秒；看到「启动成功」即可。
3. 打开飞书，私聊机器人即可提交周例会纪要。

生产环境建议改用 systemd（见 meeting-minutes-bot.service.example），开机自启并崩溃自动拉起。
若已用 systemd，就不要再同时执行「启动机器人.sh」。

二、三个快捷脚本

启动机器人.sh      后台启动（nohup + PID 文件）
停止机器人.sh      停止由启动脚本拉起的进程
查看运行日志.sh    打印最近业务日志与启动标准输出/错误

三、重要：同一时间只能有一个实例运行

本程序使用的飞书应用与开发电脑 / Windows 便携包是同一个。
服务器启动后，必须停止其他机器上的纪要机器人，否则会抢同一条消息。

四、常用飞书指令

普通成员（私聊机器人）：
  直接发文字、图片、文字版 PDF、Word 或 Markdown  —— 追加到本周纪要
  Word 中的表格和图片会在管理员生成周报时原样嵌入
  查看我的纪要 / 撤回本周提交 / 替换：完整新内容

管理员（私聊机器人）：
  查看本周提交状态 / 生成本周纪要 / 重载人员配置 / 校验配置
  也可私聊上传 people.yaml 或与正式模板同名的 .docx 热更新配置

详细说明见随包的「用户使用说明.md」和「管理员使用说明.md」。

五、人员与模板变更（可不重启）

- 飞书上传：管理员私聊发送 .yaml/.yml，或与正式模板同名的 .docx
- 或编辑 程序/meeting_minutes_bot/config/people.yaml 后发送「重载人员配置」

六、自动提醒

每周日 17:00 和 20:00（Asia/Shanghai）私聊提醒未提交人员；进程必须在跑。

七、注意事项

1. 保持目录结构完整，不要单独挪走「程序」目录内文件。
2. 包内含飞书 App Secret 与成员 open_id，勿上传公开网盘或仓库。
3. 关机或升级前先 ./停止机器人.sh（或 systemctl stop）。
4. 提交数据默认保留 14 天。
5. 本包必须在 Linux x64（建议 Ubuntu 24.04）上由构建脚本生成，不能在 Windows 上交叉编译。
