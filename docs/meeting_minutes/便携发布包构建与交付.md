# 周例会纪要机器人便携包构建与交付

面向"直接把机器人交给同事运行"的场景：目标电脑无需安装 Python，解压后双击「启动机器人.cmd」即可后台运行。飞书聊天仍是唯一业务界面。

与销售机器人的便携包完全独立：不同 EXE、不同启动器、不同数据目录和日志目录，互不影响。

## 生成发布包

在项目根目录执行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\packaging\windows\meeting\build_meeting_portable.ps1
```

脚本依次执行：校验配置与模板路径为相对路径且文件存在、跑完整 pytest、准备固定版本 PyInstaller（`.venv` 无 pip 时自动改用 `uv`）、构建、组装目录、生成 ZIP 并打印文件数、字节数和 SHA-256。

调试构建流程时可加 `-SkipTests` 跳过测试，正式交付前必须完整执行一次。

产物：

```text
release/周例会纪要机器人/
release/周例会纪要机器人-Windows-x64.zip
```

## 包内结构

```text
周例会纪要机器人/
  启动机器人.cmd / 停止机器人.cmd / 查看运行日志.cmd
  使用说明.txt / 用户使用说明.md / 管理员使用说明.md
  launcher/
  程序/
    MeetingMinutesBot.exe
    .env.meeting-minutes                              # 当前配置原样复制
    meeting_minutes_bot/config/people.yaml            # 当前人员名单
    meeting_minutes_bot/templates/周例会纪要模板.docx
    data/meeting_minutes/   logs/meeting_minutes/     # 均为空
    _internal/                                        # 依赖、OCR 模型、原生 DLL
```

发布包不携带任何历史提交、附件缓存或已生成的 Word；接收方从零开始记录。包体约 155 MB，其中约 30 MB 是随包的 OCR 模型，确保离线可用、不会在运行时联网下载。

## 两条硬约束

- **同一飞书应用同一时刻只能有一个实例在跑。** 发布包沿用当前 `.env.meeting-minutes`，交付后必须停止开发电脑上的纪要机器人，否则两个长连接会争抢同一条消息。
- **包内含 App Secret 与真实 `open_id`。** 只能通过 U 盘、局域网或加密压缩包点对点交付，禁止上传公开网盘或提交 Git（`release/` 已被 `.gitignore` 排除）。

## 交付步骤

1. 停止开发电脑上的纪要机器人。
2. 传输 ZIP，并单独告知 SHA-256 供对方校验。
3. 在目标 Windows 10/11 x64 电脑上完整解压到本地磁盘。
4. 双击「启动机器人.cmd」，等待「启动成功」。首次启动需加载 OCR 模型，约十几秒。
5. 在飞书中验证：普通成员发文字和图片、`查看我的纪要`；管理员 `查看本周提交状态`、`生成本周纪要`、`重载人员配置`。

## 更新

改完代码后重新执行同一脚本，用新 ZIP 整体替换目标电脑上的旧目录。替换前先双击「停止机器人.cmd」，不要覆盖仍在运行的程序文件。若只是人员变动，不需要重新打包，改 `程序\meeting_minutes_bot\config\people.yaml` 后让管理员发送 `重载人员配置` 即可。
