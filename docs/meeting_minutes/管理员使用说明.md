# 周例会纪要机器人 · 管理员说明

在用户说明基础上，管理员可额外使用下列能力。权限以 `people.yaml` 顶层 `admins` 名单为准。

## 管理指令（私聊原样发送）

| 指令 | 作用 |
| --- | --- |
| `查看本周提交状态` | 已提交 / 未提交名单 |
| `生成本周纪要` | 生成并回传本周 Word（带版本号；成员 Word 中的表格/图片会原样嵌入） |
| `重载人员配置` | 重新加载磁盘上的 `people.yaml`，免重启生效 |
| `校验配置` | 只读体检：人员 YAML、模板路径与占位符是否一致 |

## 私聊上传配置（推荐，免登服务器）

管理员私聊直接发送文件即可热更新，校验通过后立即生效；失败则**不覆盖**线上文件。

| 上传内容 | 文件要求 | 效果 |
| --- | --- | --- |
| 人员名单 | `.yaml` / `.yml` | 校验后覆盖正式 `people.yaml` 并热替换内存名单 |
| Word 模板 | 文件名必须与正式模板 **完全同名**（忽略大小写） | 校验占位符后覆盖正式模板 |

注意：

- 管理员本人若要提交本周纪要 Word，请使用**与正式模板不同名**的文件名，否则会被当成换模板。
- 成功时会把旧文件备份到 `data/meeting_minutes/config_backups/`（保留最近 20 份）。
- 若新 YAML 的 `admins` 未包含你自己，仍会生效，但回复会警告，且你将失去后续管理权限。
- 改 `.env.meeting-minutes`（密钥、群开关等）仍需**重启进程**。

## 人员变更 SOP

| 场景 | 操作 | 改模板？ |
| --- | --- | --- |
| 离职 | 该人 `enabled: false`（保留条目） | 否 |
| 新人顶替 | 改该槽位的 `open_id`、`name`，`enabled: true` | 否（推荐） |
| 全新岗位 | 新增条目 + 正式模板增加 `{{ template_key }}` | 是 |

推荐流程：本地改好 YAML/模板 → 私聊上传 → 看机器人回复 → 需要时发 `校验配置`。

备选（已能登录服务器改文件时）：改磁盘 YAML 后发 `重载人员配置`；模板同路径覆盖后下次生成会读新文件，建议先 `校验配置`。

- `open_id` 必须来自**本纪要应用**；让新人先私聊机器人，从日志取 `ou_...`。

## 服务器稳定运行

- **单实例**：同一飞书应用同一时刻只跑一个进程（含 Windows/Linux 便携包与开发机）；锁文件为 `logs/meeting_minutes/meeting_minutes_bot.lock`。
- **持久目录**：`.env.meeting-minutes`、人员 YAML、正式模板、`data/meeting_minutes/`、`logs/meeting_minutes/` 放在可写持久盘；勿把真实密钥与人员 YAML 提交 Git。
- **进程守护（Windows）**：用「任务计划程序」开机启动 `.venv\Scripts\python.exe -m meeting_minutes_bot`（或 Windows 便携包启动脚本），并设置失败重启。
- **进程守护（Ubuntu，推荐源码 + systemd）**：固定服务器优先按 [Ubuntu 源码 systemd 部署与升级](Ubuntu源码systemd部署与升级.md) 安装 `meeting-minutes-bot.source.service.example`。`Restart=always`，且 **60 秒内最多自动重启 5 次**，超限停止并等待管理员 `reset-failed` 后处理。代码/`requirements`/`.env` 变更需 `systemctl restart`；人员与模板热更新一般不必重启。
- **便携包（Ubuntu）**：需要免系统 Python 时再构建 Linux 便携包，见 [Linux便携发布包构建与交付](Linux便携发布包构建与交付.md)；便携包 systemd 示例同样带 60s/5 次启动限流。
- **备份**：除自动 `config_backups` 外，建议定期备份 `meeting_minutes.db` 与 `output/`；保留期默认 14 天会清理旧附件与提交源 DOCX。
- **健康检查**：定期私聊 `校验配置`；看 `logs/meeting_minutes/meeting_minutes_bot.log` 或 `journalctl -u meeting-minutes-bot`。

## 运行与产出（摘要）

- 启动：`.venv\Scripts\python.exe -m meeting_minutes_bot`
- 配置：`.env.meeting-minutes`、人员 YAML、正式 Word 模板
- 产出：`data/meeting_minutes/output/`（生成的纪要）
- 配置备份：`data/meeting_minutes/config_backups/`
- 日志：`logs/meeting_minutes/meeting_minutes_bot.log`
- 提醒开关：`MEETING_BOT_REMINDER_ENABLED=false` 可关闭周日催交
- 数据默认保留 14 天；勿提交真实 `.env`、人员 YAML、附件与日志到 Git
