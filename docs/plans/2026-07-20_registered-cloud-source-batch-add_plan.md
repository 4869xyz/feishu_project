# 固定云表链接批量登记实施计划

**状态：** 已完成  
**创建日期：** 2026-07-20  
**负责人：** Codex

## 目标与决策

- 扩展 `添加云表`，允许一条消息携带多个 Sheets/Wiki 链接，空格和换行均可作为分隔。
- 按链接首次出现顺序登记，以“链接类型 + Token”稳定去重；原单链接命令和普通临时链接处理保持兼容。
- 每个新来源独立执行导出、A:T 销售结构校验和 latest 缓存提交；一项失败不回滚已经成功的来源，也不阻断后续链接。
- 批量处理结束后只回复一次，分别列出新增编号、已有来源和按输入位置标识的失败原因，不回显 Token 或底层错误详情。

## 实施结果

- [x] 客户端链接解析层新增有序、多链接、去重提取接口，并保留原第一条链接接口。
- [x] 监听器支持跨行批量添加命令，复用现有原子缓存和结构校验流程。
- [x] 已登记来源直接跳过；导出、权限、格式或本地缓存单项失败时继续处理剩余链接。
- [x] 单链接回复保持兼容，批量回复汇总成功、已存在、失败和当前总数。
- [x] 更新 README、架构、客户端边界、SOP、测试说明和版本记录。
- [x] 增加链接顺序/去重、混合类型批量成功和部分失败继续的离线测试。

## 验收

- 空格或换行分隔的多条 Sheets/Wiki 链接按输入顺序形成连续数字编号。
- 同一消息重复链接不会重复导出，已经登记的来源不会刷新或改变原顺序。
- 中间链接失败时，前后有效链接仍能成功登记，回复不泄露链接 Token 或异常原文。
- 单链接登记、普通链接临时上传、排序、删除、清空和汇总刷新行为不变。
