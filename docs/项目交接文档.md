## 1. 项目是什么

这是一个 **Python 3.11 飞书长连接机器人**，没有 Web 后台、没有数据库入库。

业务同事在飞书里：

1. 上传销售 Excel，或发送飞书 Sheets / Wiki 表格链接；
2. 也可以把常用云表登记为「固定云表」；
3. 发送「汇总」；
4. 机器人按固定 SOP 生成一份签约汇总 `.xlsx`，作为文件回复发回当前会话。

核心约束：

- 只做 **签约数据汇总**；**回款汇总已暂停**，不读取源回款表，也不改模板里的回款表。
- 源码运行和 Windows 便携包运行走同一套数据流；便携包只是把 Python 环境冻进 EXE。
- 所有批次按 **「当前聊天 + 当前发送人」** 隔离。群里每个人的云表和临时文件互不影响。

## 3. 当前能做什么、明确不做什么

### 3.1 已上线能力

| 能力 | 说明 |
| --- | --- |
| 直接上传 Excel | 下载 `.xlsx` / `.xls` / `.xlsm` 到 `data/inbox/`；**汇总引擎只接受 `.xlsx`** |
| Sheets 链接 | `https://*.feishu.cn/sheets/<token>` 导出为 XLSX |
| Wiki 链接 | `https://*.feishu.cn/wiki/<token>` 先解析真实对象，仅 `sheet` / `bitable` 可导出 |
| 固定云表 | 长期登记，每次「汇总」前重新导出最新内容 |
| 临时来源 | 直接传文件或直接发链接；成功汇总后清空 |
| 签约汇总 | 按 SOP 重建模板中的签约目标表，发回飞书 |
| 黄色/橙色隐藏 | C:G 非空关键字段为黄/橙色时隐藏明细行，数据仍参与合计 |
| 管理员清缓存 | 「清空下载缓存」删除非活动本地文件 |
| Windows 便携包 | 目标电脑无需安装 Python |

### 3.2 明确不在范围内

- 不写数据库、不提供 Web/桌面业务界面。
- 不写入飞书 Wiki / 云文档，只读取并导出。
- 不做开机自启；Windows 重启后要手动再启动。
- 没有「帮助」「撤销」「删除某一份临时文件」命令。
- 一条普通消息只处理 **第一个** 受支持表格链接；多份长期来源请用「添加云表」。
- 不按姓名或内容去重：不同来源里相同明细会全部保留。
- 排名表、明细表、回款表不会随签约数据联动更新。
- 条件格式「算出来的显示色」不参与黄/橙色隐藏判定。

## 4. 给业务同事的使用说明

更完整的命令范例见根目录 [`飞书机器人完整对话指令规范.md`](../飞书机器人完整对话指令规范.md)。便携包内还有 `使用说明.txt`。

### 4.1 私聊与群聊

- 私聊：直接发命令或文件。
- 群聊：必须 **直接 @ 当前机器人**，命令/链接和 `@` 放在同一条消息里。
- 只 `@所有人` **不会** 触发机器人。

### 4.2 推荐日常流程（固定云表）

```text
添加云表
https://xxx.feishu.cn/sheets/sht111111
https://xxx.feishu.cn/wiki/wik222222
```

然后：

```text
云表列表
汇总状态
汇总
```

以后只要改飞书原表，再发「汇总」即可。固定云表会跨多次汇总保留。

### 4.3 全部命令

| 指令 | 作用 |
| --- | --- |
| `添加云表 <链接…>` | 长期登记一份或多份 Sheets/Wiki；空格或换行分隔 |
| `云表列表` | 查看编号和顺序（编号永远是连续的 1…N） |
| `云表排序 3 1 2` | 必须写全当前全部编号，不能重复 |
| `移除云表 2` | 移除一份固定云表并重新编号 |
| `清空云表` | 清当前用户在当前会话的全部固定云表（无二次确认） |
| `汇总状态` | 同时看固定云表和临时文件 |
| `汇总` | 刷新固定云表 + 临时文件，生成并回传 Excel |
| `清空汇总` | 只清临时来源，保留固定云表 |
| `清空下载缓存` | 仅管理员；清本地非活动文件 |

实际汇总顺序永远是：**固定云表（按编号）→ 临时文件（按加入顺序）**。

### 4.4 业务上必须知道的结果规则

- 输出只重建签约汇总表；回款表保持模板原样。
- 人员 / 客户简称 / 产品或项目 / 落地地点 / 客户来源（C:G）里，**有内容** 且字体为黄/橙色时，该明细行会自动隐藏；空白格子上残留的黄色样式不会隐藏。隐藏行仍计入合计。
- 金额列为无货币符号、1 位小数的会计专用格式。
- 用 Excel/WPS 打开结果后会重算公式；不要把尚未打开过的公式缓存当成程序算错。

## 5. 如何运行

### 5.1 开发机（源码）

环境：Windows，Python 3.11。

```powershell
python -m venv .venv
.venv\Scripts\activate
python -m pip install -r requirements.txt
copy .env.example .env
```

编辑 `.env`，至少填写：

- `FEISHU_APP_ID`
- `FEISHU_APP_SECRET`
- `FEISHU_SALES_TEMPLATE_PATH`（相对项目根目录的 `.xlsx`）

仓库里可用的样例模板：

```text
./excel_file_example/汇总效果-合并版-2026年销售数据统计2.xlsx
```

注意：`.env.example` 里曾写过 `./output/...` 路径。`output/` 是运行产物目录，**不要把历史汇总结果当成模板**。新环境请指向 `excel_file_example/` 下的模板，或业务确认过的正式模板副本。

启动：

```powershell
.venv\Scripts\python.exe feishu_bot_listener.py
```

测试：

```powershell
.venv\Scripts\python.exe -m pytest
```

同一项目目录不能同时跑两个监听器。已有实例时会报：

```text
启动失败：飞书机器人监听器已经在运行；请先停止旧实例后再启动。
```

正常退出后锁会释放；`logs/feishu_bot_listener.lock` 文件可以留着。

### 5.2 生产交付（Windows 便携包）

这是给「不会配 Python 的使用人」的方式。详细步骤见 [`WINDOWS_PORTABLE_DEPLOYMENT.md`](WINDOWS_PORTABLE_DEPLOYMENT.md)。

在项目根目录构建（会先跑完全部测试，再复制 **当前** `.env` 和模板）：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\packaging\windows\build_portable.ps1
```

产物（已被 Git 忽略，含 App Secret）：


目标电脑：

## 6. 飞书开放平台配置

机器人使用 **长连接（Channel）**，不是 HTTP Webhook 回调。应用必须是企业自建应用，并开启机器人能力。

### 6.1 本项目会调用的接口

| 用途 | 接口 |
| --- | --- |
| 下载聊天附件 | `GET /im/v1/messages/{message_id}/resources/{file_key}` |
| 解析 Wiki 节点 | `GET /wiki/v2/spaces/get_node?token=` |
| 创建导出任务 | `POST /drive/v1/export_tasks`（`file_extension=xlsx`） |
| 轮询导出 | `GET /drive/v1/export_tasks/{ticket}` |
| 下载导出文件 | `GET /drive/v1/export_tasks/file/{file_token}` |

表格链接导出至少需要：

```text
wiki:node:retrieve
drive:export:readonly
```

也可以申请更完整的 `wiki:wiki:readonly`。另需机器人收发消息、下载消息资源、发送文件的 IM 权限（以开放平台当前权限名为准）。

### 6.2 两层权限，缺一不可

1. **开放平台 API Scope**：应用后台勾选并发布权限。
2. **具体文档/知识库节点授权**：把应用加到对应知识库或云文档，并具备阅读 + 导出。

只开了 API 权限、但没把应用加入某个 Wiki 节点时，用户会收到：

> 已收到 Wiki 表格链接，但机器人没有读取该知识库节点的权限。  
> 请确认当前应用已加入该知识库或文档，并拥有节点阅读和云文档导出权限，然后重新发送链接。

### 6.3 消息准入（代码写死，不在 .env）

`feishu_bot_listener.py` 中 `PolicyConfig`：

- 私聊开放；
- 群聊开放，但必须直接 @ 机器人；
- `@所有人` 不触发。

改这三项等于改产品行为，需要先写计划再改。

## 8. 代码地图（接手改功能时从这里进）

完整依赖方向见 [`ARCHITECTURE.md`](../ARCHITECTURE.md)。分层不能反着依赖：

```text
config  →  clients / services  →  feishu_bot_listener.py
```

监听器只编排消息、下载和回复，不要把 HTTP、链接解析、汇总算法、文件命名细节塞进去。

| 路径 | 职责 |
| --- | --- |
| `feishu_bot_listener.py` | 长连接入口、命令识别、串行文件任务、回复 |
| `config/settings.py` | 读 `.env`、建目录、冻结 EXE 时改根路径 |
| `clients/feishu_client.py` | tenant token、下载、Wiki、导出任务 |
| `clients/feishu_attachment.py` | 解析文件消息、Excel 后缀、收件箱安全文件名 |
| `clients/feishu_table_export.py` | 识别 Sheets/Wiki 链接并导出 |
| `services/sales_workbook_aggregator.py` | 选表、校验、重建签约汇总、控制总额 |
| `services/aggregation_batch_store.py` | 按聊天+发送人持久化批次和固定云表 |
| `services/download_cache.py` | 限定目录内清理非活动文件 |
| `packaging/windows/` | PyInstaller 构建与中文启停脚本 |
| `tests/` | 全部 fake/mock，不访问真实飞书 |
| `excel_file_example/2026年销售数据汇总SOP.md` | **签约业务规则的事实来源** |

改汇总规则时，必须同时改 SOP 和对应测试，不能只改代码。

## 9. 本地数据落在哪里

运行产物默认都在项目根（或便携包 `程序/`）下，**全部 Git 忽略真实文件**：

| 路径 | 内容 |
| --- | --- |
| `data/inbox/` | 聊天直接上传的附件：`<message_id>__<安全文件名>` |
| `data/archive/YYYY-MM/<sender_open_id>/` | 链接导出归档 |
| `data/aggregation/state/` | 批次 JSON（临时列表、已处理来源 ID、固定云表登记） |
| `data/aggregation/registered/<owner-hash>/<cloud-id>/latest.xlsx` | 固定云表最近一次通过校验的缓存 |
| `data/aggregation/output/YYYY-MM/<owner-hash>/` | 生成的汇总结果 |
| `logs/feishu_bot_listener.log` | 运行日志（已脱敏） |
| `logs/feishu_bot_listener.lock` | 单实例锁 |
| `logs/feishu_bot_launcher.pid` | 仅便携包启动器使用 |

下载先写同目录 `.part`，成功后再改名。残留 `.part` 表示中断，排障后可手动删。

清理边界：

- `清空汇总`：只去掉当前用户临时引用，**不删磁盘文件**。
- `清空云表`：清当前用户固定登记和对应 latest。
- `清空下载缓存`：扫 `inbox/`、`archive/`、`aggregation/output/`；**不扫** `state/` 和 `registered/`。

换电脑或换目录等于换了一套本地状态。固定云表不会跟着人自动迁移，需要在新环境重新「添加云表」。

## 10. 日常运维

### 10.1 健康检查

1. 进程是否在跑（源码窗口，或便携包启动后 4 秒内未退出）。
2. 私聊发「汇总状态」，应有中文回复。
3. 日志最后几行没有连续的长连接异常。

### 10.2 磁盘

附件、归档和历史汇总会越积越多。由白名单管理员在飞书发送「清空下载缓存」。清理前会保护仍被活动批次引用的源文件。

### 10.3 不要做的事

- 不要提交 `.env`、`release/`、真实 Excel、日志。
- 不要在日志或工单里粘贴 App Secret、完整 tenant token。
- 不要同时启动源码实例和便携包实例（会抢同一把锁，或对飞书重复回复）。
- 不要在机器人正在生成 Excel 时强杀进程；先确认空闲再点「停止机器人.cmd」。

2. 用 Excel/WPS 打开结果，确认部门年度合计重算后为 **4196000**，飞书回复中的签约控制总额一致。
3. 群聊不 @ 机器人应无响应；`@所有人` 应无响应；直接 @ 应处理。
4. 发一条无权限的 Wiki 链接，应出现节点授权提示。
5. 「添加云表」后改云表内容，再「汇总」，结果应是新数据而不是旧 latest。
6. 故意让某一份固定云表失效，整次汇总应中止，且不拿旧缓存顶上。

## 14. 常见故障排查

| 现象 | 优先检查 |
| --- | --- |
| 启动立即失败，提示已在运行 | 先停旧实例；检查是否源码和便携包同时开 |
| 配置错误 | `.env` 三个必填项、模板路径是否相对且文件存在 |
| 群里没反应 | 是否直接 @ 了机器人；命令是否和 @ 在同一条 |
| Wiki 提示没权限 | API Scope **以及** 节点共享是否都给了应用 |
| 链接能打开但导出失败 | Token 必须来自 URL 路径，不是查询参数；Wiki Token 不能当表格 Token |
| 上传成功但不进批次 | 是否不是 `.xlsx`，或表头/组别/金额不符合 SOP 第 6 节 |
| 汇总中止 | 固定云表任一刷新失败都会整单失败；看回复里是哪一份 |
| 结果里公式显示 0 或空 | 用 Excel/WPS 打开让它重算，不要只看 openpyxl 缓存 |
| 不该隐藏的行被藏了 | 看 C:G 是否真有内容且字体偏黄橙；空白格残留黄样式按设计不应隐藏 |
| 「清空下载缓存」提示未启用 | `.env` 未配管理员，或改完没重启 |
| 无权限清理 | 发送人 `open_id` 不在白名单 |
| 便携包点启动后马上退出 | 看 `程序/logs/startup_stderr.log` 和 `feishu_bot_listener.log` |
| 电脑重启后机器人没了 | 预期行为；再点「启动机器人.cmd」 |

日志位置：

- 源码：`logs/feishu_bot_listener.log`
- 便携包：解压目录下 `程序/logs/`，或双击「查看运行日志.cmd」

对外发日志时先确认没有密钥和完整 token。格式化器会把 URL 里的 `access_key` / `ticket` / `access_token` / `app_secret` 打成 `***`，但不要假设万无一失。

## 15. 关键业务规则（精简版）

完整条文以 SOP 为准。接手人至少要记住：

1. 多工作表按名称优先级选签约表：精确 `签约情况` → 精确 `签约数据` → 同时含「签约+情况」→ 同时含「签约+数据」；单工作表无论叫什么都当签约表。
2. `签约汇总`、`签约排名` 不会被选中。
3. 表头第 2 行 A:I、第 3 行 I:T 的月份名必须能匹配（空白差异可兼容，文字不能改）。
4. 人员键是「组别 + 人员原文」；`A` 和 `A ` 会被当成两个人。
5. 幂等只针对飞书来源 ID，不针对业务内容。
6. 成功汇总并成功把文件发回飞书后，才清空临时批次；生成失败或回传失败则全部保留，便于重试。
7. 固定云表刷新失败 **禁止** 使用旧 `latest.xlsx` 顶替。

```text
展示用-2026年签约数据汇总（0702统计）
```
