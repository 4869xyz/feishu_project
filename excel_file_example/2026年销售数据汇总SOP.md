# 2026 年销售数据汇总 SOP

**状态：** 当前生效

**适用版本：** 签约独立汇总；回款汇总暂停

**代码对齐日期：** 2026-07-16

## 1. 文档目的

本 SOP 是当前项目处理销售 Excel 的业务和技术验收口径。程序接收一个或多个有序 `.xlsx` 源文件，从每个工作簿中选择一个签约工作表，将全部有效签约明细写入销售汇总模板，并生成新的 `.xlsx` 结果文件。

当前处理方式是**以模板为基础，清空签约业务区域后完全重建**，不是在旧汇总结果后追加：

1. 源文件和原始模板不被覆盖；
2. 目标模板只要求签约汇总工作表存在；
3. 签约目标表第 4 行及以后全部清除并重新生成；
4. 回款表、排名表、明细表和其他非签约目标工作表不参与业务处理；
5. 输出为新的 Excel 工作簿，仍然保留模板整体结构和非目标工作表。

回款解析和写入函数虽然可以作为未接入代码保留，但**不属于当前运行路径，也不属于当前验收范围**。

## 2. 文件和工作表范围

### 2.1 源文件

- 每次汇总至少需要一个源文件；
- 当前汇总引擎只接受 `.xlsx`；`.xls`、`.xlsm` 或其他格式即使已下载，也不能加入汇总批次；
- 文件名不参与业务判断，不得把实验文件名写死在代码中；
- 多个源文件严格按加入当前批次的顺序处理；
- 每个源文件必须带有非空、稳定的 `source_file_id`。

`2026年销售数据-实验1.xlsx` 和 `2026年销售数据-实验2.xlsx` 只用于本 SOP 的样例验收，不是固定输入文件名。

### 2.2 签约工作表选择

每个源工作簿只选择一个签约工作表。

1. 工作簿只有一个工作表时，无论名称是什么，都直接选择该工作表；
2. 工作簿有多个工作表时，按以下固定优先级选择：
   1. 去除名称首尾空格后，精确等于 `签约情况`；
   2. 去除名称首尾空格后，精确等于 `签约数据`；
   3. 去除名称首尾空格后，同时包含“签约”和“情况”；
   4. 去除名称首尾空格后，同时包含“签约”和“数据”；
3. 同一级存在多个候选时，选择工作簿顺序最靠前的工作表；
4. `签约汇总`、`签约排名` 等只包含“签约”、但不同时包含“情况”或“数据”的名称不作为候选；
5. 名称匹配只用于选择，程序返回和回复中显示工作簿内的实际工作表名称；
6. 当前代码不按工作表的显示或隐藏状态过滤候选；
7. 多工作表但没有任何候选时拒绝该文件，并在错误信息中列出现有工作表名称。

### 2.3 目标模板

目标模板路径由 `.env` 中的 `FEISHU_SALES_TEMPLATE_PATH` 配置。模板必须存在、后缀为 `.xlsx`，并包含：

```text
展示用-2026年签约数据汇总（0702统计）
```

当前只允许重建该签约目标表。

以下工作表存在时必须保持原样，缺失时不报错：

- `展示用-2026年回款数据汇总(0702统计)`；
- `展示用-签约排名汇总（0702统计）`；
- `明细`；
- 其他所有非签约目标工作表。

非目标工作表不会根据新签约数据联动更新，因此不纳入签约数据一致性验收。

## 3. 当前飞书运行流程

### 3.1 上传和加入批次

1. 用户直接上传 Excel 附件，或发送可导出的飞书 Sheets/Wiki 表格链接；
2. 文件下载或导出到本地后，立即执行源文件身份、签约工作表、表头和有效行校验；
3. 校验成功后，机器人回复实际选中的签约工作表名称和有效明细数；
4. 文件按“聊天 ID + 发送人 `open_id`”加入独立批次，不同发送人的批次不混合；
5. 批次顺序就是后续汇总的源文件处理顺序。

### 3.2 批次命令

| 命令 | 当前行为 |
| --- | --- |
| `汇总状态` | 显示当前发送人的活动批次文件数量和处理顺序。 |
| `清空汇总` | 只移除当前发送人的活动批次引用，不立即删除本地源文件。 |
| `汇总` | 使用当前活动批次和配置模板生成签约汇总 Excel。 |

汇总文件成功生成并成功发送回飞书后，当前活动批次才会清空。校验失败、生成失败或文件回传失败时，当前批次保留，便于排查和重试。

### 3.3 输出位置

机器人生成的结果保存在：

```text
<FEISHU_AGGREGATION_DIR>/output/YYYY-MM/<批次所有者哈希>/
2026年销售数据汇总-YYYYMMDD-HHMMSS-<随机标识>.xlsx
```

`FEISHU_AGGREGATION_DIR` 默认是 `data/aggregation/`。结果路径不得与模板或任一源文件相同。

## 4. 已确认的业务规则

1. 当前批次中的所有有效源文件都参与汇总。
2. 不按人员、客户、项目、月份、金额或整行内容进行业务去重。
3. 两个不同来源的明细即使内容完全相同，也必须分别保留和计入。
4. 不同组的同名人员视为不同人员。
5. 同一组内完全相同的人员名称视为同一人员，其多条明细合并到同一个人员区域。
6. 组别和人员保留源表原始文本，不映射为模板中的旧人员，也不主动去除业务值首尾空格。
7. 每个人固定生成月度、季度和年度三行个人汇总。
8. 每个小组无论人数多少，都固定生成月度、季度和年度三行小组汇总。
9. 所有小组后固定生成月度、季度和年度三行部门汇总。
10. 允许删除签约业务区域中的旧隐藏行；新生成区域中仅 C:G 关键字段带黄色/橙色字体的业务明细隐藏，汇总行和空行全部可见。
11. 允许通过完整重建修复原签约目标表中的数据错位、漏算和公式错误。
12. 回款读取、校验、计算和生成全部暂停；任何源回款表问题都不得阻断签约汇总。
13. 排名表和 `明细` 表不联动更新。
14. 有效签约明细 A:T 的字体颜色逐单元格保留；其他视觉样式继续由目标模板统一提供。
15. C:G 任一关键字段带黄色/橙色字体的明细只设置 Excel 行隐藏，不删除值或排除计算；个人、小组和部门汇总继续包含这些明细。
16. 签约目标表 I:T 的业务明细及个人、小组、部门月度/季度/年度金额统一使用会计专用格式：1 位小数、无货币符号。
17. I:T 每个月份列按其金额显示长度独立自适应，只向外扩展且不小于模板原宽度或 12 个字符宽。

## 5. 文件身份和幂等规则

业务明细不去重，幂等只基于来源标识执行。

### 5.1 汇总引擎

- 有序源文件列表不能为空；
- 每个 `source_file_id` 必须非空；
- 同一次汇总调用中，两个源文件的 `source_file_id` 相同时，整个任务直接拒绝；
- 不使用文件名、文件哈希或业务字段推断两个来源是否相同；
- 两个不同 `source_file_id` 即使指向内容相同的文件，也分别参与汇总。

### 5.2 飞书批次

- 批次状态持久化保存已经处理过的来源 ID；
- 对同一个“聊天 + 发送人”，已经出现过的 `source_file_id` 不会再次加入后续活动批次；
- `清空汇总` 和成功汇总只清除活动列表，不清除已处理来源 ID 记录；
- 不同聊天或不同发送人的状态相互隔离。

每次汇总均从原始目标模板重建，不以上一次输出作为模板。因此，对相同模板和相同有序输入重复调用汇总引擎时，业务数据和公式结构应一致。

## 6. 源签约表校验

### 6.1 表头校验

程序对表头执行 Unicode NFKC 规范化，并移除所有空白字符后比较。因此换行或普通空格差异可以兼容，但文字内容必须一致。

第 2 行必须包含以下表头：

| 列 | 必须匹配的表头 |
| --- | --- |
| A | 组别 |
| B | 序号 |
| C | 人员 |
| D | 客户简称 |
| E | 销售产品名称/项目名称 |
| F | 落地地点 |
| G | 客户来源（展会需注明） |
| H | 备注 |
| I | 签约后且收到第一笔款后才算已签约 |

第 3 行的 I:T 必须依次为：

```text
1月、2月、3月、4月、5月、6月、7月、8月、9月、10月、11月、12月
```

当前代码不把第 2 行 J:T 或第 3 行 A:H 作为表头校验键。

### 6.2 有效行判断

从第 4 行扫描到工作表 `max_row`，每行读取 A:T。

1. 先检查 A:H 是否出现个人、小组、部门的月度、季度或年度合计标签；匹配时执行 NFKC 归一化、清理空白并兼容末尾冒号，命中后整行跳过，且不更新当前组别；
2. A 列非空时必须是文本，并更新当前组别；只有 A 列组别、C 列人员为空的标题行仍可为后续明细提供继承组别；
3. C 列为空或只有空格时，整行作为非业务行静默跳过，不校验该行 I:T；因此个人汇总、说明文字、公式、数字或 `-` 均不会进入结果；
4. C 列非空时必须是文本，数字或布尔值仍拒绝；
5. C 列存在有效人员但无法从本行或前文取得组别时拒绝文件；
6. 有效人员行的 I:T 金额只能是 `int`、`float`、`Decimal` 或空值，布尔值不视为金额；
7. 有效人员行中的数字字符串、公式字符串、`/` 或其他非空文本不能作为签约金额；
8. 金额空值在独立控制总额计算时按 0 处理；
9. B 列序号、D:H 业务字段和月份金额不要求全部填写；B、D:H 当前不做额外类型校验，按源值写入目标表。

单个源文件可以通过结构校验但得到 0 条有效明细；只有当整个汇总批次合计仍为 0 条有效签约明细时，`汇总` 才会失败并提示“所有源文件均没有有效签约明细”。

### 6.3 错误定位

表头、组别、人员或金额错误应尽量报告：

```text
源文件名 / 实际选中的工作表 / 第 N 行 / X 列：错误原因
```

任一源文件无效时，整个汇总任务失败，不输出部分结果。

## 7. 签约字段映射

| 源签约表 | 字段 | 目标签约表 | 写入规则 |
| --- | --- | --- | --- |
| A | 组别 | A | 空值继承前一条非空组别；用于分组和 A 列合并。 |
| B | 序号 | B | 保留源值，不全局重编号。 |
| C | 人员 | C | 保留源值；人员键为“组别 + 人员”。 |
| D | 客户简称 | D | 直接写入。 |
| E | 销售产品名称/项目名称 | E | 直接写入。 |
| F | 落地地点 | F | 直接写入。 |
| G | 客户来源（展会需注明） | G | 直接写入。 |
| H | 备注 | H | 直接写入。 |
| I:T | 1 月至 12 月签约金额 | I:T | 按月份直接写入，源空值保持为空；统一设置无货币符号、1 位小数的会计专用格式。 |

源金额空值在目标明细中保持空白，但被 `SUM` 公式和控制总额按 0 处理。

除值映射外，每条有效明细还逐格保存 A:T 的源字体颜色。A 列组别由空值继承时，其字体颜色同时继承最近一次非空组别单元格的颜色。

行级隐藏只检查继承前的 C:G 原始字体样式，依次对应人员、客户简称、销售产品名称/项目名称、落地地点和客户来源；这五列任一字体命中黄色/橙色即隐藏整条明细。RGB、主题色和索引色解析为显示 RGB 后转为 HSV：色相 `20°–70°`、饱和度不低于 `15%`、亮度不低于 `35%` 视为黄色/橙色。A:B、H:T 的颜色完全不参与隐藏判定，因此月份金额变黄不会误隐藏 C:G 为黑色的行。自动色、无颜色和无法解析的颜色不触发隐藏；条件格式计算出的动态显示色不参与判定。

## 8. 稳定顺序和分组规则

为保证输出稳定，使用首次出现顺序：

1. 源文件按当前批次顺序；
2. 同一文件内按源行号升序；
3. 小组按全部源文件中首次出现的顺序；
4. 小组内人员按该组内首次出现的顺序；
5. 同一人员明细按“源文件顺序 + 源行号”排列。

分组键使用源表中的组别和人员字符串原值。除空值判断外，当前代码不对业务名称做大小写、全半角或首尾空格归一化。例如 `A` 与 `A ` 会被视为不同人员。

## 9. 模板格式样本和清理边界

### 9.1 必需格式样本

签约目标表必须能够提供以下现有样式行：

- 一行签约明细样式；
- `个人月度合计：`、`个人季度合计：`、`个人年度合计：`；
- `小组月度合计：`、`小组季度合计：`、`小组年度合计：`；
- `部门月度合计：`、`部门季度合计：`、`部门年度合计：`；
- 可复用的人员间空行和组别间空行样式。

缺少签约目标表或任一样式样本时，模板校验失败。回款表不提供也不读取格式样本。

### 9.2 清理规则

保存样式样本后，对签约目标表执行：

1. 保留第 1 至 3 行；
2. 删除所有与第 4 行及以后相交的旧合并区域；
3. 删除第 4 行至原 `max_row` 的全部旧明细、汇总、公式、空行和隐藏行；
4. 删除第 4 行及以后原有的行维度设置；
5. 不清理其他工作表。

模板不应存在从第 1 至 3 行跨入第 4 行及以后业务区域的必要合并单元格，因为这类合并会按业务区域合并关系删除。

### 9.3 格式复用

新业务行先复用样式样本中 A:T 的完整单元格样式和行高，包括字体、填充、边框、对齐、自动换行及数字格式；写入明细值后，再逐格仅将字体颜色替换为对应源单元格颜色，并将 I:T 数字格式统一覆盖为会计专用一位小数。支持保留 RGB、主题色、索引色、自动色及 tint。

源字体名称、字号、粗体、斜体、下划线等属性不复制，背景填充、边框、对齐、行高和数字格式也不从源表复制。除 I:T 金额格式由程序强制统一外，其他格式继续来自模板。个人、小组、部门汇总行及空行不读取源表旧汇总行颜色，完全使用模板颜色。条件格式动态计算出的显示颜色不在本规则范围内。

新行统一设置为非折叠、无大纲级别；只有按上述规则判定的业务明细设置为隐藏，其他明细、汇总行和空行均非隐藏。

除 I:T 金额列按数据自适应宽度外，其他列宽、前 3 行标题和表头、打印设置等工作表级配置不主动重建，继续沿用模板现有设置。只复用样式，不复用样本中的旧人员、客户、金额或公式。

## 10. 签约目标表生成结构

从目标表第 4 行开始生成。

### 10.1 人员区域

每个人员区域依次包含：

1. 该人员的全部签约明细；
2. `个人月度合计：`；
3. `个人季度合计：`；
4. `个人年度合计：`；
5. 如果同组后面还有其他人员，增加一行人员间空行。

同组最后一名人员的“个人年度合计”之后固定增加一行个人汇总分隔空行，再开始生成该组的“小组月度合计”。明细与本人的“个人月度合计”之间不增加空行。

| 行类型 | 标签区域 | 金额区域 |
| --- | --- | --- |
| 个人月度合计 | B:H 合并 | I:T 分别显示 12 个月合计。 |
| 个人季度合计 | B:H 合并 | I:K、L:N、O:Q、R:T 分别合并为 Q1 至 Q4。 |
| 个人年度合计 | B:H 合并 | I:T 合并为年度值。 |

### 10.2 小组区域

每个小组固定生成：

1. `小组月度合计：`；
2. `小组季度合计：`；
3. `小组年度合计：`。

小组汇总的标签和金额合并结构与个人汇总一致。小组结束后，如果后面还有其他组，增加一行组别间空行；最后一个小组结束后，也固定增加一行小组汇总分隔空行，再开始部门汇总。

A 列从该组第一条明细行合并到该组“小组年度合计”行，包含人员间空行和个人汇总与小组汇总之间的分隔空行，但不包含组别间空行，也不包含小组汇总与部门汇总之间的分隔空行。合并区域的首格写入组别名称，视觉样式继承模板明细和汇总行样式。

### 10.3 部门区域

所有小组后固定生成：

1. `部门月度合计：`；
2. `部门季度合计：`；
3. `部门年度合计：`。

“部门月度合计”前固定存在一行小组汇总分隔空行。

部门三行的标签区域使用 A:H 合并；季度和年度金额区域的合并方式与个人、小组汇总一致。

## 11. 签约公式

假设某人员明细行为 `start:end`，个人月度合计行为 `p`：

```excel
Ip = SUM(Istart:Iend)
```

该公式向右生成至 T 列。

个人季度和年度公式为：

```excel
Q1 = SUM(Ip:Kp)
Q2 = SUM(Lp:Np)
Q3 = SUM(Op:Qp)
Q4 = SUM(Rp:Tp)
年度 = SUM(Ip:Tp)
```

小组月度合计只引用该组每个人的“个人月度合计”单元格，不直接汇总整组区域，避免把明细和个人汇总重复计算。小组季度、年度以小组月度合计行为基础计算。

部门月度合计只引用每个小组的“小组月度合计”单元格。部门季度、年度以部门月度合计行为基础计算。

所有公式使用本次生成后的明确行号和有界范围，不使用整列引用，也不引用已删除的旧行。季度和年度合并区域只在左上角单元格保存公式。

## 12. 控制总额、计算模式和输出验证

### 12.1 独立控制总额

程序使用 `Decimal` 对全部有效明细的 I:T 源金额求和，得到 `signing_total`。该值不依赖 Excel 公式缓存，并在飞书汇总完成回复中显示：

```text
汇总完成：N 份源文件，签约 M 条 / X 元。
```

### 12.2 Excel 公式计算边界

当前 Python 代码使用 `openpyxl` 写入公式，但不在本地执行 Excel 公式计算。输出工作簿会设置为：

- 自动计算模式；
- 打开时执行完整计算；
- 强制全量重算。

因此，用 Microsoft Excel 或兼容软件打开结果文件后，应由表格软件重算并显示公式结果。不得把尚未重算的公式缓存值当作 Python 汇总失败。

### 12.3 当前运行时验证

正式输出前，程序执行以下检查：

1. 扫描新签约业务区域中的文本或公式，拒绝包含 `#REF!`、`#DIV/0!`、`#VALUE!`、`#NAME?`、`#N/A` 的内容；
2. 保存后重新打开临时 `.xlsx`，确认签约目标工作表仍然存在；
3. 确认 C:G 暖色标记明细全部隐藏、仅其他列变色的明细及汇总/空行全部可见；
4. 确认 I:T 的数字和公式单元格均为无货币符号、1 位小数的会计专用格式；
5. 确认 I:T 每列宽度与生成时计算值一致且 `bestFit` 已保存；
6. 验证通过后使用原子替换生成最终输出文件；
7. 无论成功或失败，都删除生成过程中的临时文件。

当前运行时代码不会计算公式结果，也不会通过公式缓存重新核对部门合计。公式引用、合并范围、非目标表保留和控制总额由确定性生成逻辑及自动化测试覆盖；人工验收时仍应使用 Excel/WPS 打开并检查重算后的显示结果。

## 13. 非目标工作表和回款隔离

### 13.1 当前回款规则

- 不查找源文件中的 `Sheet2`、`回款情况` 或 `回款数据`；
- 不检查回款表头、人员、金额、公式或有效明细数；
- 源回款工作表缺失、名称异常、内容错误或金额非法均不影响签约；
- 不要求模板包含回款目标表；
- 模板回款表存在时，不清空、不插行、不改公式、不改隐藏状态；
- 飞书上传和汇总完成回复不显示回款条数或金额。

### 13.2 OOXML 保留方式

模板经 `openpyxl` 保存后，程序会从原模板恢复所有非签约目标工作表的工作表 XML 及其关联部件，避免模板中的图片、绘图关系等不受 `openpyxl` 完整支持的对象丢失。若原模板使用共享字符串，还会恢复 `sharedStrings.xml` 并补齐工作簿关系，保证保留工作表和最终文件可以重新打开。

签约目标表是唯一不从原模板恢复的工作表，因为它必须保留本次重建结果。

### 13.3 未来恢复回款

当前源码中保留的旧回款解析和写入函数没有接入 `aggregate_sales_workbooks()`。未来恢复回款时，必须重新确认源工作表选择、字段映射、模板范围、公式、控制总额、异常隔离和测试计划，不能仅通过调用旧函数直接上线。

## 14. 失败和事务规则

- 源文件无法打开、不是 `.xlsx`、路径不存在或 `source_file_id` 为空时拒绝；
- 多工作表找不到签约候选时拒绝；
- 表头、组别、人员或签约金额校验失败时拒绝；
- 整个批次没有任何有效签约明细时拒绝；
- 模板不存在、不是 `.xlsx`、缺少签约目标表或缺少样式样本时拒绝；
- 输出路径覆盖模板或任一源文件时拒绝；
- 任一文件处理失败时不生成部分汇总结果；
- 飞书汇总失败时保留当前活动批次；
- 结果已生成但飞书文件回传失败时，输出文件保留，当前活动批次也保留；
- 只有结果文件成功回传后，才清空当前活动批次。

源文件下载成功但表格校验失败时，该文件不会加入汇总批次，但下载文件可能仍保留在本地缓存中。

## 15. 下载缓存清理

本节是运行维护规则，不改变签约汇总业务结果。

配置 `FEISHU_CACHE_ADMIN_OPEN_IDS` 后，白名单管理员可以向机器人发送：

```text
清空下载缓存
```

命令清理以下配置目录中的非活动文件：

- `FEISHU_INBOX_DIR`，默认 `data/inbox/`；
- `FEISHU_ARCHIVE_DIR`，默认 `data/archive/`；
- `FEISHU_AGGREGATION_DIR/output/`，默认 `data/aggregation/output/`。

以下内容必须保留：

- 所有聊天和发送人的活动批次仍引用的源文件；
- 汇总模板；
- `data/aggregation/state/` 批次状态；
- `.gitkeep`。

未配置管理员时命令禁用；非管理员执行时不扫描、不删除。单个文件删除失败不阻断其他文件清理，机器人回复删除文件数、释放空间、活动文件保留数和失败数。

`清空汇总` 只清除当前发送人的活动引用。相应源文件要等到管理员再次执行 `清空下载缓存` 后才会从本地删除。

## 18. 当前实现顺序

```text
1. 接收有序源文件列表、目标模板路径和输出路径
2. 校验源文件列表非空以及 source_file_id 唯一
3. 校验源文件路径、.xlsx 后缀和 source_file_id
4. 单表直接选择；多表按签约名称优先级选择
5. 校验所选签约表第 2、3 行表头
6. 解析第 4 行以后的 A:T 签约有效明细，保存逐单元格字体颜色并按 C:G 黄色/橙色计算隐藏标记
7. 汇总所有源文件记录并计算 Decimal 签约控制总额
8. 打开模板并取得签约目标表和格式样本
9. 清除签约目标表第 4 行以后的旧业务区域
10. 按首次出现顺序生成明细、个人、小组和部门区域，在个人与小组、最后小组与部门汇总块之间插入模板空行；明细先应用模板样式，再覆盖源字体颜色、I:T 会计格式和预期隐藏状态
11. 写入月度、季度和年度公式，对汇总金额应用相同会计格式，按月份金额长度设置 I:T 自适应列宽，并设置打开时全量重算
12. 保存临时工作簿并恢复非目标工作表 OOXML 部件
13. 重新打开临时结果，检查错误标记、金额格式、I:T 列宽/`bestFit` 及每行实际/预期隐藏状态
14. 原子替换为最终 .xlsx 输出并返回源文件数、明细数和签约控制总额
```

后续修改代码、测试或模板时，必须同时检查并更新本 SOP；如果要恢复回款汇总，应先形成新的明确规则和验收清单。
