# 2026 年销售数据汇总 SOP

**状态：** 规则已确认，可用于后续代码设计与测试  
**确认日期：** 2026-07-15

## 1. 文档目的

本 SOP 规定如何读取多个同结构销售数据文件，将其中的签约数据和回款数据汇总到目标统计工作簿。

本次处理采用**清空后重建**，不是在目标表旧业务数据后追加：

1. 保留目标工作簿及两张目标表的展示格式；
2. 清除两张目标表原有的业务明细、汇总公式、隐藏行和旧合并区域；
3. 仅使用本次输入的所有源文件重新生成签约汇总和回款汇总；
4. 生成新结果文件，不覆盖源文件和原始目标模板。

## 2. 文件与工作表范围

### 2.1 本次源文件

- `2026年销售数据-实验1.xlsx`
- `2026年销售数据-实验2.xlsx`

后续代码不得把文件名写死为以上两个名称。一次任务可以接收一个或多个同结构 `.xlsx` 文件，并按任务输入顺序处理。

每个源文件包含：

| 工作表 | 数据类型 | 有效数据起始行 |
| --- | --- | --- |
| `Sheet1` | 签约数据 | 第 4 行 |
| `Sheet2` | 回款数据 | 第 4 行 |

### 2.2 目标模板

当前模板文件：`汇总效果-合并版-2026年销售数据统计2.xlsx`

本任务只允许重建以下两张工作表：

| 目标工作表 | 重建内容 |
| --- | --- |
| `展示用-2026年签约数据汇总（0702统计）` | 签约明细、个人汇总、小组汇总、部门汇总 |
| `展示用-2026年回款数据汇总(0702统计)` | 回款明细、个人小计、部门总计 |

以下工作表不在处理范围内，代码不得写入、清空、插行或修复：

- `展示用-签约排名汇总（0702统计）`
- `明细`

这两张非目标表可能不会反映重建后的新增人员和数据，不纳入本任务验收。

## 3. 已确认的业务决策

1. 一次任务中的所有源文件都参与汇总。
2. 不按业务字段对不同源文件的明细去重。
3. 即使两条明细内容相同，只要来自两个不同的源文件，也必须分别计入。
4. 人员名称按源表原值使用，不映射为目标模板中的旧人员。
5. 目标签约表和回款表的旧业务内容全部清除，只保留并复用格式。
6. 每个人固定生成个人汇总；每个小组无论人数多少，都固定生成小组汇总。
7. 回款明细中的派生列 `I`、`J`、`K`、`N` 统一重写为公式，不采用源表已有计算结果。
8. 允许删除目标业务区域中的隐藏行；重建后的业务行全部可见。
9. 允许通过完整重建修复目标两张业务表中原有的数据错位、漏算和公式错误。
10. 签约排名表和 `明细` 表不联动更新。

## 4. 输入校验与幂等规则

### 4.1 文件级幂等

业务明细**不去重**，幂等只在文件级执行：

- 同一个源文件在一次任务中只能出现一次；
- 每个输入文件必须携带稳定的 `source_file_id`：飞书场景使用“消息 ID + 文件资源 ID”，本地批处理使用规范化绝对路径；
- 如果同一文件被重复加入同一任务，第二次应跳过或直接报错；
- 不得使用人员、客户、金额、月份等业务字段判断两个文件是否重复；
- 两个不同的 `source_file_id` 即使文件内容或业务明细完全相同，也要分别计入；
- 文件内容哈希只能用于完整性检查，不能作为跨文件业务去重键。

每次执行均从目标模板重新生成结果，不在上一次输出结果上继续追加。因此，对同一组输入重复执行时，输出数据和汇总结果应保持一致。

### 4.2 源文件结构校验

读取数据前必须校验：

1. 文件可以正常打开且为 `.xlsx`；
2. 同时存在 `Sheet1` 和 `Sheet2`；
3. `Sheet1` 的主要表头与 A:T 字段结构匹配；
4. `Sheet2` 的主要表头与 A:AC 字段结构匹配；
5. 目标模板存在两张指定目标工作表；
6. 校验未通过时终止整个任务，不得生成部分汇总结果。

### 4.3 有效行判断

`Sheet1`：

- 从第 4 行扫描到工作表最后一个实际有值的行；
- B:T 全部为空的格式占位行跳过；
- A 列组别为空时，继承上一条非空组别；
- 有业务内容但无法取得组别，判定为数据错误；
- C 列人员为空但该行其他业务字段非空，判定为数据错误；
- I:T 只能为数值或空值，空值在计算时按 0 处理。

`Sheet2`：

- 从第 4 行扫描到工作表最后一个实际有值的行；
- A:AC 全部为空的格式占位行跳过；
- A 列姓名为空但其他字段非空，判定为数据错误；
- F、G、H、L、M、O、R:AC 中需要参与计算的金额必须为数值、空值或模板允许的 `/`；
- `/` 仅表示无数值，汇总公式使用 `SUM` 时按 0 处理。

## 5. 目标模板清理与格式复用

### 5.1 清理边界

签约汇总表：

- 保留第 1 至 3 行的标题、表头、月份表头及其格式；
- 第 4 行开始的旧业务明细、旧汇总、旧公式、旧空行和隐藏行全部删除；
- 删除所有与第 4 行及以后区域相交的旧合并单元格。

回款汇总表：

- 保留第 1 至 3 行的标题、表头、月份表头及其格式；
- 第 4 行开始的旧业务明细、旧小计、旧公式、旧空行和隐藏行全部删除；
- 删除业务区域中的旧合并单元格（如果存在）。

不得清除其他工作表内容。

### 5.2 格式模板

删除旧业务区域前，应读取并保存以下格式样本：

签约汇总表：

- 明细行；
- 个人月度、季度、年度合计行；
- 小组月度、季度、年度合计行；
- 部门月度、季度、年度合计行；
- 人员间空行和组别间空行。

回款汇总表：

- 明细行；
- 个人小计行；
- 人员间空行；
- 部门总计行。

重建时复用样本的：

- 行高和列宽；
- 字体、字号、加粗和字体颜色；
- 填充色、边框和对齐方式；
- 自动换行；
- 数字、金额、日期和百分比格式；
- 目标表原有的表头合并和打印设置。

只复用格式，不复用样本行中的人员、客户、金额、公式或其他旧业务内容。

## 6. 签约数据读取与字段映射

### 6.1 字段映射

| 源表 `Sheet1` | 字段 | 目标签约表 | 规则 |
| --- | --- | --- | --- |
| A | 组别 | A | 空值向下继承；用于分组和 A 列合并 |
| B | 序号 | B | 保留源值，不进行全局重编号 |
| C | 人员 | C | 保留源值；人员键为“组别 + 人员” |
| D | 客户简称 | D | 直接写入 |
| E | 销售产品名称/项目名称 | E | 直接写入 |
| F | 落地地点 | F | 直接写入 |
| G | 客户来源（展会需注明） | G | 直接写入 |
| H | 备注 | H | 直接写入 |
| I:T | 1 月至 12 月签约金额 | I:T | 按月份直接写入；空值计算时为 0 |

### 6.2 顺序规则

为保证每次执行结果稳定，采用以下顺序：

1. 源文件按任务输入顺序；
2. 同一文件内按源行号升序；
3. 小组按首次出现顺序；
4. 小组内人员按首次出现顺序；
5. 人员明细按“源文件顺序 + 源行号”排列。

不同组出现同名人员时，视为不同人员。相同组内出现相同人员名时，视为同一人员的多条明细。

## 7. 签约汇总表生成结构

从目标表第 4 行开始生成。

### 7.1 每个人员区域

每个人员区域依次包含：

1. 该人员的全部签约明细；
2. `个人月度合计：`；
3. `个人季度合计：`；
4. `个人年度合计：`；
5. 如后面还有同组人员，追加一行人员间空行。

格式和合并规则：

| 行类型 | 标签区域 | 金额区域 |
| --- | --- | --- |
| 个人月度合计 | B:H 合并、右对齐、加粗 | I:T 分别显示 12 个月合计 |
| 个人季度合计 | B:H 合并、右对齐、加粗 | I:K、L:N、O:Q、R:T 分别合并 |
| 个人年度合计 | B:H 合并、右对齐、加粗 | I:T 合并 |

### 7.2 每个小组区域

每个小组无论只有一人还是多人，都必须生成：

1. `小组月度合计：`；
2. `小组季度合计：`；
3. `小组年度合计：`。

小组汇总格式与个人汇总格式一致。小组结束后，如后面还有其他组，追加一行组别间空行。

A 列从该组第一条明细行合并到该组“小组年度合计”行，包含人员间空行，但不包含组别间空行。合并后的 A 列显示组别名称并水平、垂直居中。

### 7.3 部门区域

所有小组后固定生成：

1. `部门月度合计：`；
2. `部门季度合计：`；
3. `部门年度合计：`。

部门标签区域使用 A:H 合并；季度和年度金额合并规则与个人汇总一致。

## 8. 签约公式规则

假设某人员明细行为 `start:end`，个人月度合计行为 `p`：

- `Ip = SUM(Istart:Iend)`，向右填充至 T；
- 个人 Q1：`SUM(Ip:Kp)`；
- 个人 Q2：`SUM(Lp:Np)`；
- 个人 Q3：`SUM(Op:Qp)`；
- 个人 Q4：`SUM(Rp:Tp)`；
- 个人年度：`SUM(Ip:Tp)`。

小组月度合计只汇总该组各人员的“个人月度合计”单元格，不直接汇总整个组区域，避免把明细和个人汇总重复计算。小组季度、年度合计以小组月度合计行为基础计算。

部门月度合计只汇总各组的“小组月度合计”单元格。部门季度、年度合计以部门月度合计行为基础计算。

所有公式必须使用本次生成后的明确行号和有界范围，不使用整列引用，不引用已删除的旧行。

- 如果现实中存在同名但不同人员，上传前必须在 A 列增加可区分标识，代码不猜测身份。

## 10. 回款汇总表生成与公式

### 10.1 明细公式

对于目标回款表第 `r` 行明细：

```excel
Ir = SUM(Rr:ACr)
Jr = SUM(Hr:Ir)
Kr = Fr-Jr
Nr = IFERROR(Jr/Fr,0)
```

说明：

- `SUM(Hr:Ir)` 可以忽略 `/` 等文本；
- 当合同总价为空或为 0 时，回款比例显示 0；
- N 列使用百分比格式；
- I、J、K、N 不复制源表的静态值。

### 10.2 个人区域

每个人员区域包含：

1. 该人员的全部回款明细；
2. 一行 `个人小计：`；
3. 如后面还有其他人员，追加一行空行。

个人小计规则：

- F:M、O、R:AC 对该人员全部明细求和；
- N 列使用 `IFERROR(个人J小计/个人F小计,0)`，不得把明细回款比例直接相加；
- P、Q 为文本字段，个人小计行保持空白；
- A:C、E 保持空白，`个人小计：` 写入 D 列；
- 小计行格式复用目标模板的个人小计样式。

### 10.3 部门总计

所有人员区域后生成一行 `部门总计：`：

- F:M、O、R:AC 汇总所有人员小计；
- N 列使用 `IFERROR(部门J总计/部门F总计,0)`；
- P、Q 保持空白；
- `部门总计：` 写入 D 列；
- 不直接对全部明细和个人小计混合求和，避免重复计算。

## 11. 公式修复与异常处理

由于两张目标业务表采用完整重建，原业务区域中的错误公式和错位数据不保留。新生成结果必须扫描：

```text
#REF!
#DIV/0!
#VALUE!
#NAME?
#N/A
```

任一目标业务表出现上述错误时，任务验收失败，不得把临时结果替换为正式输出。

其他异常规则：

- 金额字段出现无法解析的非空文本时，报告文件名、工作表和源行号；
- 人员或组别缺失时，不得自动归入“未知人员”或“未知组别”；
- 目标模板缺少格式样本或指定工作表时立即终止；
- 任一文件处理失败时，整个任务失败，不输出部分结果；
- 临时文件写入成功并通过校验后，再原子替换为最终输出文件。

## 14. 建议实现顺序

```text
1. 接收目标模板和有序源文件列表
2. 校验文件级唯一标识，拒绝同一文件重复输入
3. 校验每个源文件的工作表和表头
4. 读取并标准化所有 Sheet1 / Sheet2 有效行
5. 计算独立的期望明细数和金额控制总数
6. 复制目标模板为临时输出文件
7. 保存两张目标表的格式样本
8. 清除两张目标表第 4 行以后的旧业务区域和旧合并关系
9. 按首次出现顺序重建签约人员、小组和部门区域
10. 重建回款人员小计和部门总计区域
11. 写入并重算全部派生公式
12. 校验明细数量、控制总数、公式错误、合并和可见性
13. 校验通过后原子生成最终结果文件
```

代码实现和自动化测试应以本 SOP 第 3、4、12、13 节为不可变验收口径。
